# H10. Paginação

**Fase:** 3

## Objetivo

Diretório e tabelas de páginas, kernel em todos os espaços, page fault com mensagem clara.

## Critério de aceite

Dois espaços de endereço com valores diferentes no mesmo endereço virtual; acesso inválido gera a tela de page fault.

## Resultado

**Concluída.** Código em `kernel/mem/paginacao.c`; decisão D010.

- Paginação de 2 níveis com páginas de 4 KB; kernel mapeado 1:1 até 896 MB (página 0 sem mapeamento, para pegar ponteiro nulo), faixa de janelas 0x38000000-0x3FFFFFFF para dispositivos, área dos programas de 0x40000000 a 0xBFFFFFFF.
- As tabelas do kernel são criadas no boot e compartilhadas por todos os diretórios.
- `espaco_criar`, `espaco_destruir` (devolve páginas e tabelas), `espaco_mapear`, `espaco_traduzir`, `espaco_alocar`, `janela_mapear`.
- CR0: PG (paginação), WP (kernel respeita páginas só de leitura) e EM (instrução de FPU gera exceção, porque o estado da FPU não é salvo).
- Tela de falta de página explica a operação (leitura/escrita), o endereço, se a página estava ausente ou protegida e o modo (kernel/usuário).
- Teste `tests/h10_paginacao.py`: autoteste `paginacao` (mesmo endereço virtual lê 0x11111111 num espaço e 0x22222222 no outro, páginas físicas diferentes, kernel visível nos dois, tudo devolvido ao destruir) e autoteste `falta_pagina` (leitura de 0x90000000 gera a tela).
